## 📝 Standard Experiment Documentation Format

Every experiment directory contains a `README.md` following a uniform structure required for laboratory assessment:

1. **Aim**: Clear statement defining the experiment purpose.
2. **Objective**: Key learning and technical goals to accomplish.
3. **Algorithm**: Sequential step-by-step logic and mathematical foundations.
4. **Flowchart**: Graphical or workflow diagram illustrating data and control flow.
5. **Code**: Clean source code or relative link to the execution script.
6. **Output**: Execution logs, console printouts, or output figures.
7. **Result**: Analysis and discussion of obtained metrics and outcomes.
8. **Conclusion**: Summary of concepts learned and practical takeaways.

## 🧭 Navigation and Usage Guide

1. **Clone the Repository:**
   ```bash
   git clone https://github.com/vaishnavim4162/NLP---DSA0311.git
   cd NLP---DSA0311
   ```

2. **Adding Deliverables:**
   - Place assessment responses or notebooks inside the appropriate `Unit-X/Assessment-Y/` directory.
   - For lab work, open the relevant `Experiment/Experiment-X/README.md` and populate the designated sections.
   - Save capstone resources in the designated `Capstone-Project` subdirectories (`PPT`, `Reports`, `Datasets`, `Source-Code`).

3. **Tracking Changes with Git:**
   - Directories contain `.gitkeep` files to maintain structure on GitHub.
   - Once content is added, stage and commit changes cleanly:
     ```bash
     git add .
     git commit -m "feat: add submission for Unit-1 Assessment-1"
     git push origin main
     ```
